Introduction Générale
Dans un contexte de modernisation croissante des institutions publiques et militaires, la gestion efficace de la formation constitue un enjeu stratégique majeur. La formation du personnel représente un investissement conséquent qui nécessite une évaluation rigoureuse et systématique afin de mesurer son impact et son efficacité.
Les méthodes traditionnelles d'évaluation de la formation, souvent manuelles et fragmentées, ne permettent plus de répondre aux exigences actuelles en termes de rapidité, de fiabilité et de capacité d'analyse. Face à cette réalité, le développement d'un système informatique dédié s'impose comme une solution pertinente et nécessaire.
Ce projet s'inscrit dans cette dynamique en proposant la conception et le développement d'un Système d'Evaluation de la Formation et d'Aide à la Décision (SEFAD). Ce système ambitionne de digitaliser l'ensemble du cycle d'évaluation des formations, depuis la création des questionnaires jusqu'a la génération de rapports analytiques destinés aux décideurs.
Contexte et Motivation
L’école d’état-major fait face à plusieurs défis dans la gestion de ses formations : multiplicité des supports d'évaluation, difficulté de consolidation des données, absence d'outils d'analyse et lenteur dans la remontée d'informations. Ces lacunes impactent directement la qualité des décisions prises en matière de pilotage de la formation.
Objectifs du Projet
Ce projet vise a atteindre les objectifs suivants :
Centraliser la gestion des évaluations de formation sur une plateforme unique
Automatiser la collecte et le traitement des données d'évaluation
Fournir des tableaux de bord et des indicateurs de performance aux responsables
Mettre en place un module d'aide a la décision basé sur l'analyse des données
Assurer une traçabilité complète du processus d'évaluation
Structure du Rapport
Ce rapport est organisé en quatre chapitres principaux :
Chapitre 1 : Analyse des besoins - étude de l'existant et specification des besoins fonctionnels et non fonctionnels

3.1.2 Architecture du Système
Le système SEFAD adopte une architecture en couches (n-tiers) qui sépare les responsabilités et facilite la maintenance :
Couche Présentation : interfaces HTML/CSS/JavaScript generees par PHP (pattern MVC)
Couche Logique Métier : PHP pour la gestion des requetés HTTP et la logique applicative
Couche Traitement Analytique : micro services Python exposes via API REST pour les calculs statistiques et l'aide à la décision
Couche Données : MySQL avec un modelé relationnel optimise et des procédures stockées
Architecture hybride PHP + Python
Le choix d'une architecture hybride combinant PHP et Python permet de tirer parti des points forts de chaque langage. PHP assure la rapidité de développement des interfaces et la gestion des sessions, tandis que Python offre une puissance de calcul supérieure pour l'analyse de données et les algorithmes d'aide à la décision via des bibliothèques comme pandas, numpy et scikit-learn.
3.2 Developpement Back-end
3.2.1 Architecture PHP - Pattern MVC
Le back-end PHP est structure selon le patron de conception MVC (Modelé-Vue-Contrôleur) :
Modelé (Model) :
Les modelés encapsulent la logique d'accès aux données et les règles métier. Chaque entité du domaine possède sa classe modelée correspondante avec des méthodes CRUD optimisées et l'utilisation de requetés préparées pour la sécurité.
Vue (View) :
Les vues sont des templates PHP generer du HTML dynamique. Elles sont organisées par module et utilisent un système d'héritage de templates pour garantir la cohérence visuelle. Les données sont passées aux vues via le contrôleur.
Contrôleur (Controller) :
Les contrôleurs reçoivent les requetés HTTP, invoquent les modelés pour récupérer ou modifier les données, et choisissent la vue appropriée pour afficher la réponse. Un routeur central redirige les requetés vers le contrôleur compètent.
3.2.2 Gestion de la Sécurité
La sécurité a été une préoccupation centrale tout au long du développement :
Hachage des mots de passe avec bcrypt (PHP password_hash)
Protection CSRF avec tokens generes par session
Prévention des injections SQL par l'utilisation exclusive de requetés préparées (PDO)
Protection XSS par l'échappement systématique des sorties (htmlspecialchars)
Gestion des sessions avec régénération de l'identifiant après connexion
Contrôle d'accès base sur les rôles (RBAC) vérifie à chaque requête
Logs de sécurité pour la détection d'activités suspectes
3.2.3 Gestion de la Base de Données
La couche d'accès aux données utilise PHP Data Object (PDO) pour une abstraction de la base de données. Les transactions MySQL sont utilisées pour garantir l'intégrité des données lors des opérations complexes.
Extrait de la structure de la table évaluations :
Structure SQL : Table évaluations
CREATE TABLE évaluations (  id_evaluation INT AUTO_INCREMENT PRIMARY KEY,  id_utilisateur INT NOT NULL,  id_questionnaire INT NOT NULL,  date_passage DATETIME DEFAULT CURRENT_TIMESTAMP,  score_total DECIMAL(5,2),  score_maximum DECIMAL(5,2),  pourcentage DECIMAL(5,2),  statut ENUM('en_cours','termine','annule') DEFAULT 'en_cours',  FOREIGN KEY (id_utilisateur) REFERENCES utilisateurs(id_utilisateur),  FOREIGN KEY (id_questionnaire) REFERENCES questionnaires(id_questionnaire));

3.4 Module Python - Traitement Analytique et Aide à la Décision
3.4.1 Architecture du Module Python
Le module Python est deployed comme un service REST indépendant accessible via HTTP. Il est développé avec le micro Framework Flask et expose une API documentée consommée par le back-end PHP.
Les bibliothèques Python utilisées sont :
Flask: micro Framework web pour l'API REST

Numpy : calculs numériques et statistiques
Scikit-learn : algorithmes de machine Learning pour les recommandations
Matplotlib / seaborn : génération des graphiques exportables
Mysql-connector-python : connexion directe à la base de données
Reportlab : génération de rapports PDF
3.4.2 Algorithmes d'Aide à la Décision
Le module d'aide à la décision est le cœur analytique du système SEFAD. Il met en œuvre plusieurs algorithmes :
Analyse des performances :
Calcul des indicateurs statistiques (moyenne, médiane, écart-type, percentiles) pour chaque formation et formateur. Détection automatique des anomalies et des écarts significatifs par rapport aux normes établies.
Système de scoring multicritères :
Implémentation d'un modelé de scoring base sur la méthode AHP (Analytic Hierarchy Process) permettant de pondérer différents critères d'évaluation et de produire un score global composite.
Analyse des tendances :
Utilisation de modelés de régression linéaire (scikit-learn) pour identifier les tendances d'évolution des performances et projeter les résultats futurs sur la base de l'historique.
Recommandations automatiques :
Génération automatique de recommandations d'amélioration basées sur les patterns identifies dans les données d'évaluation. Le système compare les performances de chaque formation a des benchmarks établis et suggère des actions correctrices.

Annexe B : Extrait du Code Python - Module de Scoring
Code Python - Calcul du score AHP multicritères
import numpy as npimport pandas as pddef calculate_ahp_score(criteria_weights: dict, evaluation_scores: dict) -> float:    """    Calcule le score composite AHP pour une évaluation multicritères.    Args:        criteria_weights: dict {critere: poids_normalise}        evaluation_scores: dict {critere: score}    Returns:        float: Score composite normalise sur 100    """    weights = np.array(list(criteria_weights.values()))    scores = np.array([evaluation_scores.get(k, 0) for k in criteria_weights.keys()])        # Verification coherence des poids    assert abs(weights.sum() - 1.0) < 1e-6, "Les poids doivent sommer a 1.0"        composite_score = np.dot(weights, scores)    return round(composite_score, 2)
